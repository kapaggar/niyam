## Architecture in one paragraph

`GongService` is the long-lived process (foreground `mediaPlayback`): it loads Room seed data, runs `SchedulerEngine` (exact alarms + ~30 s heartbeat), and owns `PlayerEngine` (Media3). Compose UI is a **client** of the service. Pure scheduling/play rules live under `domain/` and are unit-tested on the JVM.

## Behavioural non-negotiables

Copy these; do not “simplify” them away:

- Active course = **date window**, not “starts today only”; start date is day **0**.
- Day index = calendar days between dates.
- Fire: never early; grace **120 s**; else **`missed`** (no late blast).
- Write **`fired:…` guard before play**.
- Clock untrusted (large backwards jump) → suppress automatic plays.
- Doha: `legacy_modular` when `0 < day ≤ total_days`.
- Queue: gong preempts gong; doha waits; stop clears all.
- Timezone: settings key `timezone` may pin an IANA id and a pin always wins;
  **blank (the default) means follow the device**. No hardcoded IST fallback.
- Gong `repeats` counts audible **hits**, not file plays (`GongTracks`):
  sikkim carries 3 hits per play, so a 6-repeat row plays it twice.

## Version the APK on every substantive change

**Bump `versionCode` by 1 and set a new `versionName` in
`app/build.gradle.kts`, in the same commit as the change.** Substantive means
a new or unlocked screen, a behaviour change, a media swap, a permission
added, or a fix to anything on the QA checklist — not comment-only, doc-only
or test-only edits.

A tester installs over the top. An equal `versionCode` can leave the old code
in place and a lower one is refused, so a stale APK looks exactly like a fixed
bug returning. The build is shown on the Setup screen so it can be checked
without a cable.

Bump the version line in `docs/BETA-QA-CHECKLIST.md` and name the version in
`PROGRESS.md` in the same commit. Full rationale in `AGENTS.md`
("Versioning the test APK").

## Git commit messages (mandatory)

Write messages that describe **only the work done** (what changed and why).

**Do not** add contribution or tooling placeholders, including:

- `Co-Authored-By: Claude …` / `Co-Authored-By: …@anthropic.com`
- `Claude-Session: …` or any session URL
- `Generated by …`, `Made with …`, or similar agent watermarks
- Empty trailer blocks or marketing fluff about the model

Preferred shape:

```text
Short imperative summary (≤ ~72 chars)

Optional body: what changed and why it matters.
Mention tests run when relevant.
```

Examples of good subjects: `Fix double-fire guard on process death`, `Add PIN gate with PBKDF2`.  
Not: multi-paragraph model self-credit or session links.
