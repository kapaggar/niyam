# B2 — Downloads UI (2026-08-09)

## What was added

### `ui/AppViewModel.kt` — "doha downloads" section

Between the doha-pack section and toasts:

- `private val assetManager: AudioAssetManager by lazy { AudioAssets.get(getApplication()) }`
  — lazy so the manager (which indexes disk on creation) is only built when a
  screen first asks about downloads.
- `val downloadStates` — getter proxy of `assetManager.states`.
- `val downloadCatalog` — getter proxy of `assetManager.catalog`.
- `fun downloadsMetered()` → `isMetered()`.
- `fun downloadDoha(id)` → `request(id)` (metering consent is the screen's
  job; `allowMetered` default `true` is correct once the user has confirmed).
- `fun downloadAllDohas(allowMetered)` → `requestAll(allowMetered)`.
- `fun rescanDownloads()` → `refreshFromDisk()`.
- `fun scanStorageForMedia()` → `scanStorage()` + toast
  "Scanning storage for doha files…".

### `ui/DohaMediaScreen.kt` — Downloads section

Appended `DownloadsCard` after the folder-pack report cards, plus helpers at
the bottom of the file:

- **Rows:** 11 catalog assets sorted by filename. Leading mono tag `D01…D11`
  (`slotTag` = filename before first `_`), title from the third `_` segment
  with `Doha-` prefix stripped, trailing `-` trimmed, `-` → space
  (`D06_0632_Doha-Samatha-_NA_NA.mp3` → "Samatha", `D01…Doha-Hin-1…` →
  "Hin 1"). Rows ≥ 44 dp (`Nocturne.MIN_TOUCH_DP`).
- **State chips:** NotDownloaded → dot + "Not downloaded" + Download button;
  Downloading → mono "12 / 43 MB" (decimal MB, no decimals) +
  `LinearProgressIndicator` (Accent on Neutral800); Preparing → "Preparing…"
  (Warning dot); Ready → "Ready" in `Nocturne.Ok`; Error → message verbatim in
  Error colour + Retry button; NoKey → plain "Unavailable".
- **NoKey banner:** shown once above the list — "This build has no media key —
  downloads are disabled." Rows all show "Unavailable"; Download-all disabled.
  Detection: any state is `NoKey`.
- **First-use note:** when no key banner and every asset resolves
  NotDownloaded (missing map entry treated as NotDownloaded): large files,
  WiFi recommended, files stay on device.
- **Download all dohas (~470 MB):** unmetered → `downloadAllDohas(false)`
  directly; metered → confirm dialog "You are on mobile data. Download about
  470 MB now?" → `downloadAllDohas(true)`. Per-row Download/Retry gets the
  same dialog with "about 45 MB".
- **Scan storage for existing media:** secondary `PackButton` +
  helper line "Looks for already-downloaded doha files in common folders on
  this device."
- `LaunchedEffect` on entry now also calls `vm.rescanDownloads()` alongside
  the existing folder rescan (stale "Ready" chips are the same lie as stale
  "verified" rows).

## Judgment calls (for the Lead)

1. **No dialog idiom existed** anywhere under `ui/` (grep found zero
   `Dialog` usages), so the metered confirm is a Material3 `AlertDialog` with
   `containerColor = Nocturne.SurfaceHigh` and the screen's own `PackButton`s
   as confirm/dismiss. Swap if a house dialog appears later.
2. "Ready (accent)" rendered in `Nocturne.Ok` to match the slot list's
   "verified" green rather than the purple Accent; a purple "Ready" beside a
   green "verified" would read as two different claims.
3. MB formatting is decimal (`bytes / 1_000_000`) so a 43,375,504-byte asset
   shows "43 MB", matching the brief's example.
4. `downloadStates` is collected in the screen with
   `collectAsStateWithLifecycle` like every other flow there; the property is
   a getter proxy, which is safe because `states` is one stable StateFlow
   instance on a lazy singleton.
