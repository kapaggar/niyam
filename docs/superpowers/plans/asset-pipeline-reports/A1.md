## Semantics as implemented (for the Lead's integration review)

- Evaluation order is strictly spec 1→7; one effect per call, never loops.
- Hash compares are case-insensitive in **both** verify functions (spec only
  said so for `verifyReady`; the same helper is used for encrypted — flag if
  you want exact-case there).
- `Salted__` in ready → `MoveReadyToEncrypted` even when size/hash look wrong
  for the ciphertext: integrity of the moved file is judged in the encrypted
  slot on the re-ask, never discarded from ready.
- Blocker precedence pinned by tests: `Play` outranks everything; `NO_KEY`
  before `NO_SPACE` on the decrypt path; oversized-partial `Discard` before
  `OFFLINE`; `OFFLINE` before `NO_SPACE` on the download path.
- Space thresholds are strict `<`: exactly-at-threshold proceeds (both
  boundaries tested).
- `partialBytes == encryptedBytes` (not just `>`) is discarded — a
  complete-looking partial that never verified must not be resumed.
- Identity is id + hash: D01/D09 fixtures share title family and byte sizes;
  D09-hashed content does not verify as D01 (both plaintext and ciphertext),
  and lands in `Discard(READY)` via `next`.
- `Discard.reason` strings are short and human ("empty file", "checksum
  mismatch", "HTML error page saved as audio", `"partial larger than
  expected"` verbatim per spec). Only the PARTIAL reason is asserted exactly;
  the rest assert target only, so B1 may reword without breaking A1 tests.
- Purity: no Android, no java.io, no clocks — stdlib + `AssetTypes.kt` only.
